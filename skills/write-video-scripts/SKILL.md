# Write Video Scripts

Produce a script that can be recorded or shot, not an essay with camera labels added afterward. Keep spoken words, visible action, on-screen text, and audio directions distinct.

## Follow the workflow

### 1. Parse the brief

Extract and prioritize:

1. Objective and desired viewer action
2. Audience and awareness level
3. Platform, format, aspect ratio, and target duration
4. Topic, source material, or existing draft
5. Voice, language, and brand constraints
6. People, locations, props, footage, budget, and production limits
7. Required claims, exclusions, call to action, and compliance needs

Require at least one usable topic, source, or draft. If a required link or attachment is unavailable, say what could not be read and request the content; never imply that it was reviewed.

Resolve conflicts in this order: explicit hard constraints, supplied source material, stated preferences, format conventions, then defaults. Point out any impossible combination and produce the closest workable version when doing so would still help.

Ask no more than three concise questions only when the topic is missing, hard constraints conflict, an inaccessible source is essential, or a high-risk claim cannot be handled safely. Otherwise proceed and list only the assumptions that materially affect the result.

### 2. Set deliberate defaults

When the user leaves choices open, use:

- The user's primary language
- A general adult audience
- A 60-second vertical video
- One presenter or narrator
- One or two easy-to-access locations
- Low production complexity
- Clear, restrained, conversational delivery
- No specific statistic, testimonial, guarantee, or call to action unless the objective supports it

Override any default implied by the user's source, platform, or goal. Treat platform conventions as adaptable patterns, not permanent technical rules.

### 3. Choose the deliverable

Infer the smallest useful deliverable:

- Return a beat outline when the user asks to explore structure or ideas.
- Return spoken copy only when the user asks for a voiceover or talking-head draft.
- Return a production script when the user asks for scenes, shots, subtitles, sound, or a shootable script.
- Return a diagnosis plus revised script when the user supplies a draft to improve.
- Return clearly labeled variants when the user asks for alternatives; give each variant a distinct strategic purpose rather than swapping synonyms.

Use the production-script contract by default. Read [output contracts](references/output-contracts.md) before formatting the response.

### 4. Build the narrative spine

State one controlling idea: what should change in the viewer's understanding, feeling, or behavior?

Choose a structure from [the format playbook](references/format-playbook.md), then build:

1. A concrete viewing reason or dramatic question
2. Escalating beats with one job each
3. Evidence, demonstration, conflict, or discovery
4. A payoff that answers the opening promise
5. A call to action only when it follows naturally from the objective

Make the opening specific and relevant. Avoid empty hooks such as “you won't believe this” unless the next beat immediately earns the claim.

### 5. Budget time before drafting

Allocate seconds to each beat before writing full copy. Reserve time for pauses, reactions, demonstrations, and transitions. Use the pacing ranges in [the format playbook](references/format-playbook.md) as estimates, then read the draft aloud mentally and cut anything that forces unnatural delivery.

Do not claim frame-accurate duration from a text estimate. Label timing as estimated until a real read-through or edit confirms it.

### 6. Draft for sight and sound

- Write narration and dialogue for the mouth and ear: short clauses, intentional rhythm, speakable transitions, and contractions where natural.
- Give each visual a production purpose: reveal information, demonstrate a claim, create contrast, show emotion, or reset attention.
- Avoid making visuals mechanically repeat every spoken line.
- Keep on-screen text brief enough to scan and reserve it for names, numbers, steps, contrasts, or essential emphasis.
- Specify camera movement, transitions, music, and sound effects only when they change meaning, pacing, or execution.
- Keep shots achievable within the stated cast, location, footage, equipment, and budget limits.
- Preserve the user's meaning and factual boundaries when adapting supplied material.

### 7. Handle facts, rights, and safety

Read [factual and safety guidance](references/factual-safety.md) whenever the script includes current events, statistics, quotations, product performance, health, law, finance, allegations, real-person endorsements, dangerous activity, or copyrighted source material.

Use current authoritative sources when verification tools are available. When verification is unavailable, remove the claim, soften it without changing the core idea, or mark it clearly as requiring verification. Never invent a citation, quotation, credential, testimonial, clinical result, or product capability.

Distinguish factual narration, creative dramatization, and unresolved production notes. Replace requests to clone a living creator's exact style with high-level traits such as pacing, tone, structure, or visual density.

### 8. Run the quality gate

Read [the quality rubric](references/quality-rubric.md). Revise silently until all hard gates pass. Do not expose chain-of-thought or a long self-critique; return the finished script, material assumptions, and only the verification or production notes the user needs.

## Revise an existing script

Preserve the original goal and hard constraints unless the user asks to change them. Diagnose the highest-impact issues first: promise, structure, timing, speakability, visual execution, factual support, and call to action. Then rewrite the script rather than stopping at advice.

For a requested compression, protect the controlling idea and payoff, remove duplicate setup, combine beats, shorten examples, and simplify visuals. For expansion, add evidence, contrast, demonstration, or character development instead of padding.

## Keep scope clear

Provide prompts or production notes for downstream image, audio, editing, or video tools when helpful, but do not claim to have rendered, edited, or published a finished video unless those tools were actually used.
