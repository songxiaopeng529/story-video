# Output Contracts

Choose the smallest contract that matches the request. Preserve the user's language and requested terminology.

## Production script — default

```markdown
## Creative brief
- Objective:
- Audience:
- Platform / format / estimated duration:
- Controlling idea:
- Material assumptions:

## Script
| Time | Shot / visible action | Narration / dialogue | On-screen text | Audio / transition |
|---|---|---|---|---|
| 00:00–00:05 | ... | ... | ... | ... |

## Production notes
- Cast / locations / props:
- Capture or asset notes:
- Continuity or accessibility notes:

## Verification notes
- Verified claims and sources:
- Claims requiring confirmation:

## Delivery check
- Estimated spoken length:
- Key constraints satisfied:
- Open decisions, if any:
```

Omit empty or irrelevant sections. Keep time ranges continuous and make their total align with the estimated duration.

## Spoken-copy contract

Use for voiceover, podcast-style video, teleprompter copy, or a talking-head request that does not need shot direction.

```markdown
## Brief and assumptions
- Audience / objective / estimated duration:
- Material assumptions:

## Spoken script
[Natural, paragraph-broken copy with optional pause or emphasis cues.]

## Optional on-screen text
- ...

## Verification notes
- ...
```

Do not force a table onto spoken-only copy.

## Beat-outline contract

Use before drafting or when the user asks for structure only.

```markdown
## Direction
- Promise or dramatic question:
- Audience / format / duration:

## Beat map
1. **00:00–00:XX — Beat name**
   - Story or information job:
   - Visual opportunity:
   - Evidence or emotion:

## Risks and open decisions
- ...
```

## Revision contract

Use when improving an existing script.

```markdown
## Highest-impact diagnosis
1. ...

## Revised script
[Use the spoken-copy or production-script contract.]

## Material changes
- Changed ... because ...
```

Keep the diagnosis short. Make the revised artifact the main deliverable.

## Variant contract

Label each variant by its strategic choice, for example:

- Variant A — authority-led explanation
- Variant B — demonstration-first opening
- Variant C — character-driven reveal

Keep factual claims and hard constraints consistent across variants.

## Formatting rules

- Separate spoken words from on-screen copy.
- Number shots when the user requests a shot list or storyboard.
- Use `V.O.`, `O.S.`, scene headings, or screenplay conventions only when the requested format benefits from them.
- Label timing as estimated until a read-through confirms it.
- Cite factual sources near verification notes, not inside performance dialogue unless the source is part of the story.
- Mark unverified production placeholders as `[VERIFY]`, `[INSERT APPROVED CLAIM]`, or `[CHOOSE SHOT]`; never disguise them as finished facts.
